# barge-monitor

A system and architecture demonstrator that runs whole in one browser tab (SRD Version 4):
an OGC API – Connected Systems server in front of an awkward legacy logger, a
self-configuring display client, and models that each run in their own worker. Every
component and every real message is on screen, and the company's value-add (the display
client and the models) is marked.

**Demonstrator:** https://deepbluecltd.github.io/barge-monitor/demo/ ·
**Requirements:** https://deepbluecltd.github.io/barge-monitor/

Everything is fictional: the canal, its places and the weather.

## Layout

| Path | What |
|---|---|
| `srd-barge.md` | Software Requirements Document, Version 4 |
| `docs/v4-interfaces.md` | The implementation contract: component ids, flows, letters, resources, profile, worker protocols |
| `docs/mockups/` | The SRD's companion mockups (non-normative) |
| `contracts/` | Masters for the seam: `openapi.json` (generated by FastAPI, committed, checked by a test), `profile.json` (v4) and its JSON Schema, JSON Schemas for discovery shapes |
| `backend/barge/` | Python back end: world, sensors, logger store, store adapter, data server (FastAPI), the models' internal interface (`modelhost.py`), registry, referee scoring, message tap |
| `backend/models/` | The models: `csmodel.py` (the interface every model is written against), Data cleanse, Model A, Model B, and the example for an empty slot |
| `backend/contract_suite/` | One contract suite, run against the app under uvicorn, in Pyodide, and against the JavaScript stand-in |
| `backend/tests/` | pytest acceptance tests |
| `backend/independent/` | AT-05: OSHConnect-Python browses the server |
| `web/` | TypeScript and React: the demonstrator shell (stacked flowchart, detail panel, status, key, control panel), the display client (ECharts), the relay (Service Worker), the Pyodide back-end and model workers, the JavaScript stand-in, Playwright tests |
| `scripts/build_history.py` | Pre-calculated history: the logger files for seeds 1–3 (FR-15) |
| `docs/decisions-log.md`, `docs/adr/`, `docs/findings/` | Decisions taken while implementing, decision records, measured findings |

## Run it locally

```sh
pip install -r backend/requirements-dev.txt
(cd backend && python -m pytest -q)                      # Python tests

python scripts/build_history.py --days 7 .cache/history 1 2 3   # one week, as the tests use
cd web
npm ci
npm run pyodide          # Pyodide 0.29.5 and packages into ../.cache (once)
npm run build            # generates TypeScript types from contracts/, packs the Python
npm run site             # assembles ../dist-site/{demo,pyodide,history}
npm run serve            # http://localhost:8080/demo/
npm run e2e              # Playwright tests
```

`?backend=standin` forces the JavaScript stand-in (used automatically where WebAssembly is
blocked); `?backend=python` forces Pyodide; `?sketch=off` draws plain outlines. The
published site uses `--days 28` (four weeks).

The server also runs under an ordinary ASGI server, with the core models in-process:
`cd backend && python -c "import uvicorn; from barge.runtime import Runtime; from barge.api import create_app; rt = Runtime(pregen_days=1, local_models=True); [rt.tick() for _ in range(200)]; uvicorn.run(create_app(rt))"`.
